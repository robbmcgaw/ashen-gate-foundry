# Ashen Gate | Locations

Places in your campaign, each with a threat level, gathering resources, factions, quests, related locations and notes. You decide which parts players can see.

Module ID `ashen-gate-locations` · Foundry V14, dnd5e. Works on its own; Quest Manager, Profession Ledger and General Manager are optional partners and are feature-detected. General Manager hands location records to `importLocations`.

## Install

Foundry or The Forge: **Add-on Modules → Install Module → Manifest URL**, paste

`https://raw.githubusercontent.com/robbmcgaw/ashen-gate-foundry/main/modules/ashen-gate-locations/module.json`

and Install. Updates arrive through Check for Updates / Forge's update button. Every version is also on the [GitHub Releases](https://github.com/robbmcgaw/ashen-gate-foundry/releases) page for manual install or rollback. Change history is in [CHANGELOG.md](CHANGELOG.md).

**Version numbers:** the Ashen Gate suite is pre-release, so Locations was renumbered from 1.18.0 to **0.18.0** (October 2026). Feature notes below that say "1.x.0" refer to the old numbering and are all included in 0.18.0 and later. Foundry will not offer 0.18.0 as an update to 1.18.0 because the number is lower: uninstall Locations and install it again from the manifest URL above. Your locations, pins and Party Notes are kept: they live in the world, not in the module.

## Using it

- **GM:** Scenes sidebar → **Locations**. Click **New location**, type a name, and click **Save Changes**. The `LOC-*` ID is made from the name the first time you save and never changes after that.
- **Editor layout (0.19.0):** the editor has three sub-tabs under one footer: **Content** (type, region, threat, image and the blocks), **Visibility & map** (*Who Can See It*, which applies at once and is badged **Applies now**; *Place*; *Unidentified Marker & Pin*; *Linked Scenes*) and **Party Notes**. Switching sub-tabs keeps unsaved edits. **Place on Scene**, **Move to…** and **Delete location** are in the editor head. The toolbar is one row; **Filters (n)** opens the filters, sort, group and *Show representative-only too*.
- **Gathering nodes:** each *Gathering Resources* entry is a node with a skill, tier (1–5) and DC (10/12/15/18/20 by tier unless you change it), a common material and an optional rare one (success by 5+), quantities, *Finite* and *Available* switches, and a note. A finite node can be marked exhausted (shown struck through) and restored. Players see the DC only if you turn on its 👁. Optional *Exotic materials* (1.9.0, GM only) list Exotics the Profession Ledger may find there: random discovery, or a designated source with its own chance and condition. The skill list says *Hunting* (1.18.0; older "Skinning & Harvesting" / "Hunting/Skinning" values read as Hunting).
- **Node templates (1.18.0, Profession Ledger 0.25.0+):** instead of typing a node, choose one of the Ledger's node templates and click **Add node**. The Ledger owns the template (activity, professions, tier range, check, materials); the entry here only refers to it by its `NODE-*` id and keeps this place's name, tier, DC, DC visibility, finite, availability and note (blank / *Template* = the template's value). The template's details show read only, with a button to the Ledger's *Gathering Nodes* tab. A deleted template leaves the entry in place, marked "Node template NODE-… no longer exists". Without the Ledger you add custom nodes as before.
- **Fill it in:** drop material Items on *Gathering Resources*, Actors or Journals on *Factions*, and any Actor, Item, Journal or Roll Table on *Notes*. Or type a custom entry. Link quests from Quest Manager and other locations from the dropdowns.
- **People and Shops (0.30.0):** on a location's *Content* sub-tab. **People** is a block like Factions: drop an NPC Actor or Journal on it (or pick one and **Link**); each person has an eye (hidden by default), a name and a note for players, and the block has *Show section to players*. If General Manager imported your NPCs, the block suggests the ones whose record names this place (`found_at` and similar relations, or `location_id`; a bare `related` link is offered after, marked as only mentioning it) with **Link <name>**. A link keeps the NPC's permanent id, so after the Actor is re-imported **Re-link to <name>** points the row at the new Actor. Players see the visible names as a **People** card; a name is a link only if Foundry lets them open it. **Shops here** (GM) lists the shops linked to this place in Ashen Gate | Utilities (*Include places inside* widens it), with **Present…** (all or chosen players), **Stop showing** and **Open**; players see a **Shops** card with **Open shop** only for shops presented to them at this place. Needs Utilities 0.35.0+ (`api.shops.atPlace`, GM only; `forMe()` views carry a `placeKey` for places revealed to everyone) and degrades to nothing without it.
- **Marker state:** each location is **Hidden** (players see nothing; its pins are invisible to them), **Unidentified** (players see only its unidentified label and teaser) or **Revealed**. New locations start hidden.
- **Save vs Publish:** **Save Changes** is private. Players see your edits only after **Publish** (Reveal and Unidentified publish too). **Player Preview** shows what they would see in the location's current state (Hidden: nothing); tick *Also show the other states* to compare all three. The choice is remembered per computer. Marking a node exhausted shows at once.
- **Reorder, Add Detail, Loot, Regions (1.4.0):** drag a block's grip (or use ▲▼, or Alt+Up/Down on the grip) to reorder the card and the entries in it; players see published blocks in that order after **Publish**. **Add Detail** makes a custom block on this location. **Loot & Rewards** takes Items dragged from the sidebar or a compendium (a link only; no Actor ever gets the item) or plain rewards, with a status you set. Tick **This is a Region** to make it a folder; since 1.8.0 it passes its Conditions to every place inside it only when you also tick **Pass conditions to places inside** (off by default). A place can turn an inherited condition off or change it for itself.
- **Visibility once revealed:** each field has an 👁 toggle, each section has a *Show section to players* switch, and each entry has its own 👁 toggle.
- **Map:** **Place on Scene** adds a Map Note at the centre of your view, or drag a location from the list onto the canvas. Double-clicking the note opens the location. Hidden pins are invisible to players; unidentified pins show the label and the unidentified image. Set pin art under *Unidentified Marker & Pin* (default images are Foundry icons). **Default pin for places inside this one (0.25.0, GM):** the same section has a revealed image, a hidden / unidentified image and a size that every place inside this one inherits. A place uses its own value, else the nearest place above it that sets one, else the GM Setup unidentified image, else Foundry's icons; its own value is never changed, and a pin whose image you edited in Foundry's Note settings keeps it. Saved with the location (not published; players never receive it). Change one placed pin's image or size in Foundry's own Note settings and that pin keeps it. **Keep pin art proportions (0.27.0, GM, per location):** *Visibility & map*, next to *Pin size*. Off by default, so every existing pin stays Foundry's square. Tick it and **Save Changes** and that location's pin is drawn wider or taller to match its image (for example a banner for a district label): *Pin size* is the height and the width follows the picture, capped at 4 times the height (a tall picture is capped at a quarter of the height in the same way; a more extreme image is shown whole, smaller, inside that limit, never stretched). The frame, shading, click, hover, drag and double-click follow the new shape. **0.27.1:** the name under the pin is hidden for these pins, in both name modes, because the wide art usually carries the name; tick **Show the name under the pin** (appears beside *Keep pin art proportions* when it is on; saved with the location, not published, no Publish needed) to bring it back, drawn where *Name under the pin* puts it, measured from the new edge. **Banner width (0.27.1):** while Keep pin art proportions is on, *Banner width* (number box and slider, 48 to 1024 px in steps of 8, empty = off) draws the pin that many canvas pixels wide and the height follows the image (the same 4:1 / 1:4 limit applies and the width is still the frame width); *Pin size* is greyed with "Using Banner width" while a width is set, and "Draws about W x H" shows the result once the image has loaded. Saved with the location, in Export / Import, not published, no Publish needed. A pin whose size you changed in Foundry's own Note settings ignores the Banner width and uses that size as its height, as before. The Note's own text is unchanged, so the name is still used by Foundry's Notes layer listings and the Selected-players rule; only the drawing is hidden. It applies to whichever image the pin shows (revealed, unidentified, hidden or archived), takes effect on Save with no Publish, is saved with the location and travels in Export / Import (an update import that leaves it out keeps the world's value), and players never receive it as a setting: they only see the drawn pin. It is per location with no inheritance: *Default pin for places inside this one* does not carry it. Untick it and Save to return to the square. Foundry's marquee selection still treats a pin as its square. **Pin look (0.21.0):** GM Setup → *Map Pins* sets *Framed (Foundry default)* or *Image only* (no square, no shaded backing; the frame returns while a pin is hovered or selected), *Name under the pin* (*Only when hovering*, Foundry's own behaviour and the default, or *Always shown*; size and wrapping apply in both) and *Wrap the name after (characters)* (0 = off, or 6 to 60; breaks the displayed name at word boundaries), *Name distance from the pin* (pixels, −40 to 40, default 0 = Foundry's spot; negative = closer, try −8), *Name size* (pixels, 8 to 48, default 14; a Note whose own Font Size is set to anything but Foundry's default 32 keeps its own size). World setting, applied on every client to pins placed from Locations only; it redraws pins and rewrites nothing. Hidden pins never show a name and unidentified pins show only the unidentified label.
- **Beasts (0.32.0, GM only):** a block beside People on the *Content* sub-tab: the creature Actors that may roam here. Same Actor picker and drop as People, plus a note for you. It is GM data: it is never published, never in a player view, Player Preview, page, export for players or any player API call, even if an entry's `visible` or `sections.beasts` is true (the data layer drops it, not the UI). `visible` and `sections.beasts` default to false. Export / Import / a Manager update carry `beasts` and `sections.beasts`; an update record that leaves them out keeps the world's.
- **Region headers (0.32.0):** the list nests places under collapsible headers by Region ancestry (`isRegion` and `parentLocationId`), for the GM (*Group by Region*, the default; Tree mode is unchanged) and for players. Headers show a count of places inside, are buttons with `aria-expanded`, and which are folded is remembered per user in this browser (localStorage, failing quietly). Places with no Region above them stay in the free-text *Region* groups ("No region" last; a group with the same name as a top-level Region joins it). Players only get what they can see: a revealed Region says `isRegion` in its player view, an unidentified place is a header only when a visible place sits inside it and shows its generic label, and a hidden Region is never named: a visible place whose Region is hidden has no `parent`, so it sits in the nearest visible ancestor's header or in the flat groups. The selected place's headers and a search keep matches open.
- **Unidentified pin labels (0.32.0):** an unidentified pin's label (the generic one, e.g. "Abandoned Hamlet") is drawn under the pin all the time, in both name modes of GM Setup → Map Pins. It is read on each client from the pin's player page (state *unidentified*), so it also applies to pins already on the map and writes nothing. Revealed pins still follow *Name under the pin*. With *Keep pin art proportions* on and *show name* off, no label is drawn at all, as before.
- **Tree (1.8.0):** the **Tree** chip in the toolbar shows places inside their Regions as folders, to any depth, with counts (directly inside · in total), **Expand all / Collapse all**, and a **+** on each folder to make a place inside it. Drag a place onto a folder (or *Drop here for top level*) to move it, with **Undo**; **Move to…** on the card does the same from the keyboard. The card shows its path (Overworld › … › this). Filters and search keep the folders leading to each match.
- **Placeable on a map (1.8.0):** on by default for places, off for Regions. Representative-only places are left out of *Place on Scene* and dragging onto the map unless you tick **Show representative-only too** (under **Filters**); a place that already has a pin always shows it (and Place on Scene) on its card. The *Placeable* filter finds either kind.
- **Who Can See It (1.8.0):** **Everyone** (default) or **Selected players**. Only the ticked players get the card, its pins, its Party Notes and its quest links; everyone else gets exactly what they would for a Hidden place. Players who can see it may **Share with…** other players (adds only; the GM can turn sharing off per location). The card lists who shared with whom; untick a player to undo.
- **Everyone else sees it as unidentified (0.28.0, GM):** in **Selected players** mode, tick this and the players you did not pick get an unidentified marker at the same spot instead of nothing. They see the generic unidentified label and pin art (the location's own unidentified label if it has one, else the world's, and the same pin art an Unidentified location uses) and cannot open the real page. The picked players are unchanged: real pin, name, art and page. You see both pins on the scene (the second one's label starts with "Unidentified view:" on your screen only). A **Hidden** or archived location still shows nobody anything. It follows the real pin when you move it, and goes when you untick the option, switch back to **Everyone**, hide, archive or delete the location. Off by default; saved with the location (Export / Import); applies at once like *Who Can See It*.
- **Nesting & Scenes:** put a location inside another (any depth, no loops); the *Inside* list and *Move to…* offer Regions only (a current non-Region parent stays shown as "not a Region"; tick *This is a Region* on a container first), and the *Region* field is a drop-down of your Regions (a custom text is kept). The API still accepts any parent. Players see the places inside a revealed location once each is revealed (unidentified ones by label). Link scenes and open them with one click; only your view moves.
- **Party Notes (1.5.0):** every location players can see (Revealed or Unidentified) has a shared **Party Notes** card that the whole party edits. One person edits at a time: **Edit** takes the lock, everyone else sees "*name* is editing", and **Save Party Notes** or **Cancel notes edit** lets it go (it also lapses after 2 minutes without typing, or when that player disconnects). A save based on an older copy is refused and the text stays in the box. The GM can edit any location's Party Notes, **Take Over** from a player, and **Clear** them. They are not your *Notes* section: Save Changes, Publish, imports and exports never touch them. Hiding a location hides its Party Notes from players until it is visible again. Since 1.7.0 players can save with no GM connected.
- **Routes are retired (0.20.0).** There is no Routes tab, no legs, no journeys, no Travel tracker and no route drawings. A road, river or pass is just a location whose **Type** is *Route* (the Type field suggests it; any text is still allowed). Put it inside the place it leaves from, like any other location; it is not linked to other locations. When the party travels, the GM rules and rolls.
- **Hazards (0.20.0)** on any location's *Content* sub-tab: **Add hazard…** gives a name, a note and an optional Roll Table; **Edit…**, **Remove** (asks first), **Open table** and **Roll** (GM: draws it to chat). Drop a Roll Table on the card to add a hazard that uses it. No chance, no automation. A hazard is GM only until you show it with its 👁; players then see its name and note after **Publish**, while the place is revealed, and never its table.
- **Roll Tables (0.20.0):** link world tables (pick one and **Link**) or drop one, from a compendium too. **Roll** (GM only) draws to chat. A shown table lists its name for players, who can open it only if Foundry's own permission lets them.
- **Old routes:** routes and journeys saved by 0.19.0 and earlier stay in the world, untouched and unused. **GM Setup → Developer Tools → Convert routes to locations…** (only shown while the world has some) previews, then makes one Hidden location of type *Route* per route: a new `LOC-*` id from its name, terrain and distance as the description, inside the start location's parent (or inside the start location when that is at the top level), the old hazard table as a GM-only roll table and a GM-only hazard holding the route's GM notes. A route whose start location is gone is listed as skipped. Safe to run again: a converted route is never converted twice.
- **Active locations (0.24.0):** the editor head's **Active / Not active** button (GM, one click, applies at once; no Save or Publish) marks where the party is now. Many can be active (a Region being active implies nothing for the places inside it). A *Here now* badge shows on the place for players who can see it and they get "The party is now at …" (Unidentified places use their label; Selected-players places go only to those players). A Hidden place asks *Reveal and make active?*. **Filters → Status → Active** and an *Active* badge on list rows help the GM; players see active places first. For other modules: gathering nodes of the active places are `activeLocations()` then `resourcesAt(key)` for each (GM: full nodes; players: the nodes they may see; unidentified places have none), and the hook above says when to re-read. Active is stored on the location record and travels in the player view; it is not part of the published content, so Publish and "Players see an older version" are unaffected. Imports never switch a place on.
- **Show to Players (0.23.0):** the editor's **Show to Players** button (GM) opens that location in every other connected player's Locations window if they may see it (Hidden asks *Reveal and show* first). The window switches rather than stacking, and does not interrupt typing or unsaved Party Notes. GM Setup → *Show to Players* can switch the automatic opening off (a notification instead).
- **Select, Archive and Delete (0.26.0, GM):** **Select** in the toolbar puts a tick box on every row. Narrow the list with *Region*, the other Filters, the search box or **Id starts with** (e.g. `LOC-FRONTIER-`), then **Select all N shown**. **Archive…** previews exactly what it will do, then takes the locations off the list and out of players' sight (as if Hidden) while keeping everything: content, state, audience, Party Notes and map pins (the pins stay on the scene for you, closed to players). **Undo** shows for 30 seconds; **Archived (n)** lists them and **Restore…** brings them back. **Delete…** removes for good: preview, a one-click JSON backup of exactly those locations, then the labelled **Delete N locations** confirm (Cancel is the default). A location with places inside it can only be deleted together with them (the window offers to add them). Map Notes this module placed are removed; Notes you changed by hand in Foundry (image or size) stay and are listed. Party Notes stay stored and return if the same id is imported again. Archived locations are skipped by a re-import and stay archived; a deleted one is created again if a pack Manager imports still contains it, so archive what you want kept out of the world.
- **Players:** Actors sidebar → **Locations** (when *Player Access* is on in GM Setup; it saves with GM Setup's **Save Changes**, like the other settings there). Players get a read-only view of revealed locations. Clicking a quest opens the Quest Log; in the Quest Log, a quest's *Locations* list opens the location.

## Storage

- **Locations (GM Data)** Journal (no player permission) holds every record.
- **Locations (Player View)** Journal holds one page per location. A page contains only what players may see. Hidden locations get an empty page with no player permission, unidentified ones a page with just the label and teaser, and Map Notes point at these pages. Since 1.8.0 each page names every player in its ownership: a *Selected players* page gives only those players access (and NONE to the rest), so Foundry itself hides the page and its Map Notes from everyone else. Its pins carry no label of their own; Foundry labels them from the page for the players who may open it. Links on a card (parent, places inside, related, inherited conditions) appear only when everyone who can read that card can also see their target. As with the GM Data Journal, Foundry sends every document to every client; the permission is what keeps it out of each player's view.
  **Companions (0.28.0):** with *Everyone else sees it as unidentified* on, the same Journal also holds one generic page per such location, named with the unidentified label and holding nothing else. Its ownership is the mirror image of the real page: OBSERVER for every player who is not selected (and as the default, so a player created later gets it), NONE for the selected players. It is bound only by its own random `companionKey`, which the GM Data record maps back and which never appears on the real pin or page. On each scene the real Map Note gets a second Map Note at the same spot (same size unless you resized it) pointing at that page, with no text of its own (flags: `companionKey`, `companionFor` = the real Note's document id, and the art/size the module wrote). Limits: Foundry sends every Note to every client and hides the ones whose page a player cannot open, so a determined player could read the real pin's position, art path and random pin key from the Note data (as with any Selected-players pin since 1.8.0); the real name, text and content are never in it. Moving a real pin moves its companion when you drop it (the GM's client updates it); deleting a companion by hand brings it back on the next save of any location, so untick the option instead.
- Pages and Map Notes are bound to a location by a random **pin key**, never by the `LOC-*` id (an id is made from a name, so it could give an unidentified place away).
- **Locations (Party Notes)** Journal (no player permission) holds every location's Party Notes, by `LOC-*` id. Each visible location's player page carries a copy (no id); a hidden one's page carries none. With a GM connected, players send a request over the module socket and the primary GM's client checks it (sender, Player Access, the location is visible to players, the lock and the stamp) before writing. Notes of a deleted location are kept and come back if the same id is imported again.
- **Locations (Shared Notes)** Journal (1.7.0; players OBSERVER on the entry) holds one generic page per location visible to players, keyed by pin key, carrying only the notes copy. Players OWN those pages, so with no GM connected they save there directly (same lock and stamp rules). A Hidden location's page is blank with no player permission. The GM's client reconciles it with the GM store on login and after any player write: one-sided changes are taken; if both changed, the newer wins and the older text is kept under a divider. A player could console-edit the notes of a location they can already see (accepted trade-off).
- Foundry sends every world document to every client, so a player who digs in the browser console could read the GM Data journal. Nothing in the normal Foundry UI shows it.

- **Retired routes (0.20.0):** what 0.19.0 and earlier stored for routes is left exactly as it was and never written again: the GM Data Journal's `routes`, `routeIds` and `travel` flags, the **Locations (Routes)** Journal (player-safe route and journey pages, nothing secret), a party marker Map Note (it now opens nothing) and any route Drawing. Delete the Journal, the marker or a drawing by hand if you no longer want them; Locations never deletes them.

All these Journals live in *Ashen Gate / Locations*. Don't edit them by hand.

Journals from Locations 0.8.x are ignored (a one-line console note says how many). Delete them when you no longer need them.

## API

`game.modules.get('ashen-gate-locations').api`. For players, every read returns only revealed and visible data, and only while Player Access is on.

| Call | Returns |
|---|---|
| `listLocations({revealedOnly, includeUnidentified, placeableOnly})` | locations (GM: full records; `placeableOnly` keeps those marked Placeable on a map; players: revealed only, plus unidentified `{key, state, name, teaser?}` with `includeUnidentified`). A player view of a *Selected players* location also has `share: {userIds, canShare}` |
| `getLocation(idOrPinKey)` | one location, or `null`. Players get unidentified ones only by pin key. GM records carry `beasts` (0.32.0, creature Actor links, GM only); player views never do, and a revealed Region's view has `isRegion: true` |
| `childrenOf(idOrPinKey)` | GM: child records. Players: `[{id?, key, name}]` of revealed/unidentified children |
| `resourcesAt(id)` | gathering nodes: `[{id, label, skill, tier, dc, materialId, quantity, rareMaterialId, rareQuantity, finite, exhausted, available, note, uuid}]`. GM also gets `visible`, `dcVisible` and `exotics` (`[{materialId, mode: 'discovery'|'designated', chance?, condition?}]`); players never get `dc` unless shown, and never `exotics`. 1.18.0: an entry that refers to a Ledger node template is `{id, nodeId, label, tier, dc, dcVisible, finite, exhausted, available, note, visible}` for the GM (`null` = the template's value; resolve it with the Ledger's `templates.resolve(entry)`), and `{id, nodeId, label, skill, activity, tier, dc?, materialId, quantity, rareMaterialId, rareQuantity, finite, exhausted, available, note}` for players (the Ledger's `templates.playerView`, no chances or Exotics) |
| `nodesForMaterial('MAT-…')` | `[{locationId, locationName, matches: 'common'\|'rare'\|'both', ...node}]` |
| `locationsWithMaterial('MAT-…')` | `[{id, name, available}]` |
| GM only: `markNodeExhausted(locationId, nodeId, exhausted = true)` | the updated node; `false` restores it |
| `GATHERING` | `{skills: ['Herbalism', 'Mining', 'Fishing', 'Hunting', 'Archaeology'], dcByTier: {1: 10, 2: 12, 3: 15, 4: 18, 5: 20}, legacyDcByTier: {1: 10, 2: 12, 3: 13, 4: 14, 5: 15}}` (`legacyDcByTier`: the pre-1.9.0 table, still treated as the tier default) |
| `locationsForQuest('QUEST-…')` | `[{id, name}]` (used by Quest Manager) |
| `open()`, `openLocation(idOrPinKey)` | opens the window |
| GM only: `setLocationState(id, 'hidden'\|'unidentified'\|'revealed')`, `publishLocation(id)` | change what players see (the only calls that do) |
| GM only: `publishAllLocations()` (0.31.0) | Publish for every non-archived, non-Hidden location with unpublished changes, in one write. Resolves `{published, ids}`. Non-GM throws; a second call publishes 0 |
| GM only: `setLocationActive(idOrPinKey, bool)` (0.24.0) | marks where the party is now; many may be active. Live state like Hidden/Revealed: applies at once, no Publish. Hidden throws (reveal first). Non-GM throws. Resolves to the GM record |
| `activeLocations()` (0.24.0) | GM: `[{id, key, name, state}]` of every active one. Player: `[{key, name, state}]` of visible active ones only (the name they may see; an unidentified place has only its label); never hidden or other players' Selected-players places. Sorted by name |
| `isLocationActive(idOrPinKey)` (0.24.0) | boolean. A player gets `false` for anything they cannot see |
| Hook `ashen-gate-locations.activeChanged` (0.24.0) | `Hooks.callAll` on every client when its active set changes (not at start-up): `{keys: [pin keys active now], added: [keys], removed: [keys]}` |
| GM only: `showToPlayers(idOrPinKey)` (0.23.0) | opens the location in every other connected client's Locations window (Revealed or Unidentified; Selected-players: only those players; Hidden throws). `{sent: players reached}`. The socket message carries only the pin key |
| GM only: `previewLocation(draft, state?)`, `hasUnpublishedChanges(id)` | the player view after Publish; whether players see an older version |
| `STATES` | `['hidden', 'unidentified', 'revealed']` |
| GM only (0.26.0): `previewBulk('archive'\|'restore'\|'delete', ids)` | writes nothing; `{targets: [{id, name}], unknown, skipped, blocked: [{id, name, children, childIds}], outsideChildren, archivedParents, partyNotes, active, pins: [{uuid, name, managed, overridden}], ok}` |
| GM only (0.26.0): `archiveLocations(ids)`, `restoreLocations(ids)` | `{archived\|restored: [id], alreadyArchived, skipped: [{id, reason}]}`; `archiveLocations(ids, {source, reason})` from a source other than the window (General Manager passes `'ashen-gate-manager'`) skips a location with unlisted places inside, reason `has-children`. An archived location keeps every field and gains `archived: true`; it leaves `listLocations()` (default), `activeLocations()`, `childrenOf`, `locationsForQuest`, `locationsWithMaterial`, `nodesForMaterial` and every player view. `getLocation(id)` still reads it. Restoring never makes a place active |
| GM only (0.26.0): `deleteLocations(ids)` | permanent. Throws, changing nothing, if any id has a child that is not in `ids` (archived children count). ### `embed.mount(element, options)` (1.13.0)

Shows a compact, **read-only** Locations view inside another module's window, for example Character Hub's Ashen Gate → Locations: the revealed places the user can see, grouped by region, with search. Each place opens in the Locations window; **Open Locations** opens the window.

```js
const api = game.modules.get('ashen-gate-locations')?.api;
if (api?.embed?.mount) {
  const view = api.embed.mount(element, {actorId: actor.id, mode: 'character'});
  // later: view.refresh();  view.unmount();
}
```

- `element`: a DOM element the caller owns. Locations replaces its contents and adds the class `agl-embed`.
- `options.actorId` is accepted (places are party-wide); `options.mode`: `'character'` (the only mode; `api.embed.modes` lists them). An unknown mode or a missing element throws.
- Returns `{unmount(), refresh()}`. It refreshes itself when Locations' journals or Player Access change and unmounts itself if the element has left the page.
- **Permission:** it reads the same player views the window shows players, so players see only revealed places they may read (never hidden, unidentified details or GM fields). 0.20.0: no journey progress (journeys are retired). The GM sees the same list (what the party knows). Players see "The GM has hidden Locations." while Player Access is off; Open checks Player Access again. Nothing can be edited from the embed.

Removed in 0.20.0 (routes retired): `listRoutes`, `getRoute`, `saveRoute`, `setRouteState`, `setRouteAudience`, `deleteRoute`, `importRoutes`, `ROUTE_STATES`, the route drawing calls, every journey call (`getJourney`, `startJourney`, `nextLeg`, …) and `api.travel` (the Travel tracker, `ag-locations-travel/1`). Partners feature-detect them, so they skip routes when they are missing.

## Import format

Location records go in an `ag-foundry-import/0.2` package with `entity_type: "Location"`, so one test data pack can carry them. **General Manager imports them for you:** when Locations is active, its normal import creates the Items first and then passes the Location records to `api.importLocations` in the same run. Without Manager (or for a Locations-only file) use **Import** on the Locations tab toolbar, which reads the same records and skips other types. Either way a location whose ID already exists is kept as it is; Manager can also be told to update existing locations (`importLocations(records, {mode: 'update'})` replaces the definition but keeps its marker state, what players currently see, its pin key and exhausted nodes; publish to show the update). Imports never touch Map Notes.

**Route records** (`entity_type: "Route"`, `RTE-*` ids) are retired in 0.20.0: an import skips each one with "Routes are retired; make a location with type Route instead." and still imports the file's locations. Write a Location record with `"type": "Route"` instead.

```json
{
  "manifest": {"schema_version": "ag-foundry-import/0.2", "package_id": "AG-TEST-PACK", "version": "1.0.0"},
  "records": [{
    "id": "LOC-TEST-MILLBROOK", "entity_type": "Location", "status": "draft", "version": "1.0.0",
    "provenance": {"sources": ["synthetic test data"]}, "visibility": "player", "refs": [],
    "name": "[TEST] Millbrook",
    "location": {
      "type": "Village", "region": "[TEST] Green Vale", "threat": "normal", "state": "revealed",
      "parentLocationId": "LOC-TEST-REGION", "unidentifiedLabel": "[TEST] Mill smoke", "teaser": "…",
      "pin": {"img": "path/to/pin.webp", "unidentifiedImg": "path/to/unknown.webp", "size": 48}, "childPin": {"img": "", "unidentifiedImg": "", "size": 0}, "sceneUuids": ["Scene.abc123"],
      "description": "…", "img": "path/to/image.webp",
      "show": {"description": true},
      "sections": {"resources": true, "factions": true, "npcs": true, "quests": false, "related": true, "notes": true, "conditions": true, "loot": true},
      "isRegion": false, "layout": ["description", "loot", "detail:cellar"],
      "npcs": [{"key": "clerk", "label": "[TEST] Mira Vane", "uuid": "Actor.abc123", "docType": "Actor", "sourceId": "NPC-TEST-MIRA-VANE", "note": "The ferry clerk", "visible": false}],
      "conditions": [{"key": "fog", "label": "Dense fog", "text": "…", "visible": true}],
      "loot": [{"key": "blade", "label": "[TEST] Blade", "text": "…", "img": "path/to/img.webp", "uuid": "Item.abc123", "docType": "Item", "status": "available", "visible": true}],
      "details": [{"key": "cellar", "title": "[TEST] Cellar", "text": "…", "uuid": "", "visible": false}],
      "conditionOverrides": [{"from": "LOC-TEST-REGION", "conditionKey": "fog", "disabled": true}],
      "resources": [{"id": "reed-bed", "label": "[TEST] Reed Bundle", "skill": "Herbalism", "tier": 2, "dc": 12, "dcVisible": false,
                     "materialId": "MAT-REED", "quantity": 1, "rareMaterialId": "MAT-SILVER-REED", "rareQuantity": 1,
                     "finite": true, "exhausted": false, "available": true, "visible": true, "note": "One patch"}],
      "factions":  [{"label": "[TEST] Millers' Guild", "uuid": "Actor.abc123"}],
      "quests":    [{"questId": "QUEST-TEST-ONE"}],
      "related":   [{"locationId": "LOC-TEST-OLD-QUARRY"}],
      "notes":     [{"title": "Rumour", "text": "…", "visible": false}],
      "hazards":   [{"id": "rockfall", "name": "[TEST] Rockfall", "note": "…", "shown": false, "tableUuid": "RollTable.abc123"}],
      "rollTables": [{"id": "weather", "name": "[TEST] Weather", "uuid": "RollTable.def456", "shown": true}]
    }
  }]
}
```

- `threat` is `normal`, `hot` or `deadly`.
- Gathering nodes: every field except a name or material is optional. Defaults: `tier` 1, `dc` from the tier, `quantity`/`rareQuantity` 1, `finite` true, `exhausted` false, `dcVisible` false. Keep `id` stable; 1.0.x entries without node fields still import. `skill` "Skinning & Harvesting" or "Hunting/Skinning" reads as `Hunting`.
- 1.18.0 node template references: a `resources` entry with `nodeId` (a Profession Ledger `NODE-*` id) refers to a template, e.g. `{"id": "ford-reeds", "nodeId": "NODE-TEST-RIVER-REEDS", "tier": 2, "label": "[TEST] Reeds by the ford", "exhausted": false, "available": true, "visible": true}`. It carries only `id`, `nodeId`, `label`, `tier`, `dc`, `dcVisible`, `finite`, `note`, `exhausted`, `available`, `visible` (all but `nodeId` optional; a missing or `null` `tier`/`dc`/`dcVisible`/`finite` and an empty `label` mean the template's value). `skill`, materials, quantities, `exotics` and `uuid` belong to the template and are dropped. Full rules: [`docs/location-gathering-entries.md`](../../docs/location-gathering-entries.md).
- `show` (per field: `type`, `region`, `description`, `img`, `threat`) and every entry's `visible` default to `true`.
- `sections` default to `false`. `state` is `hidden` (default), `unidentified` or `revealed`; older files with `revealed: true/false` still import. A visible location's content is published on import.
- `parentLocationId` is an exact `LOC-*` id (a loop is refused); `type` and `region` stay free text. `pin.size` 0 or missing means 48 (or the nearest ancestor's `childPin.size`). `childPin` (0.25.0, optional, GM-only, same shape as `pin`) is the default pin for places inside this one; an update import that omits it keeps the world's.
- 1.4.0 fields, all optional: `layout` (block keys in order: `description`, `conditions`, `children`, `resources`, `factions`, `quests`, `related`, `loot`, `hazards`, `rollTables`, `notes`, `scenes`, `detail:<key>`; unknown keys are dropped and missing ones appended), `details`, `conditions`, `loot` (`status` is `available`, `discovered` or `taken`), `isRegion`, `conditionOverrides` (`from` is the Region's `LOC-*` id, `conditionKey` one of its condition keys). Loot `uuid` is a link only. An update import that leaves any of them (or the `conditions`/`loot` section switches) out keeps the world's value.
- 1.8.0 fields, all optional: `passConditions` (Regions only; a record without it is settled on import like the migration: on if it is a Region with conditions and something inside it), `placeable` (`null`/missing = on unless a Region), `audience` (`{mode: 'everyone'|'selected', userIds, sharedBy, sharing}`; user ids are world-local). An update import keeps the world's `audience` (play state, like the marker state) and keeps `passConditions`/`placeable` when left out.
- Exports also carry `pinKey` and `published` (what players currently see). An update import that leaves out `parentLocationId`, `unidentifiedLabel`, `teaser`, `pin` or `sceneUuids` keeps the world's value (see also the 1.4.0 fields above).
- 0.20.0 fields, all optional: `hazards` (`[{id, name, note, shown, tableUuid}]`; `shown` defaults to `false`, GM only; `tableUuid` an optional RollTable uuid, never sent to players) and `rollTables` (`[{id, name, uuid, shown}]`; `uuid` required, a world `RollTable.…` or `Compendium.…` uuid; `roll_tables` is read too). Keep each `id` stable. Players see a shown entry only after Publish, while the place is revealed. An update import that leaves either out keeps the world's value. New `layout` keys: `hazards`, `rollTables`. Exports also carry `convertedFromRoute` (GM only: the `RTE-*` id a Developer Tools conversion made it from, or `''`). Uuids are world-local: a table must exist in the world (or a compendium) you import into.
- Party Notes are campaign state, not definition: exports leave them out and imports never read or change them.
- **Export** (Locations tab toolbar) writes the same format. [`examples/test-locations.json`](examples/test-locations.json) is a synthetic sample; **GM Setup → Developer Tools** imports it.
