# Ashen Gate | General Manager

Module ID `ashen-gate-manager` · Foundry V14 · dnd5e. The GM hub: one importer for Ashen Gate data, a library of what was imported, shared appearance settings (GM Setup → General; **My Appearance** in the header) and Player Access on the Modules tab. It is GM-only; the other modules work without it. Open it from **Items sidebar → General Manager** (GM only).

## Tabs

Since 0.46.0 the window has six tabs, **Import · Items · NPC Codex · Modules · Scenes · GM Setup**, and text sub-tabs (no icon rails). The keyboard moves between tabs with the arrow keys; sub-tabs, folds and the Items Filters row are remembered per user. Old tab ids still work: `history` opens Import → Import history, `appearance` opens GM Setup → General, and the old Items views `codex` and `adopt` open the NPC Codex tab and GM Setup → Developer Tools.


- **Import:** load an `ag-foundry-import` JSON package, preview every record as create, update or skip, pick what to apply and apply it. It creates world Items, Journals, Actors, Roll Tables and Macros (imported Macros are never run), matched by permanent id, never by name. Quest, Skill Tree, Headquarters facility, Factions and Location records are recognised by shape and handed to those modules when they are active (otherwise skipped with a reason). Cinder definitions, powers and Backfire tables (0.39.0; schema in [`docs/cinder-strain-schema.md`](../../docs/cinder-strain-schema.md)) import as documents and their `cinder` / `power` / `backfire` blocks are checked by Ashen Gate | Cinders; a **Strain config** file (`ag-strain-config/0.1`) is handed to Cinders. Importing never creates or changes Cinder instances, bearers, progress or Strain. `ITEM-*` and `PERK-*` records may carry a **`modifiers` block** (`ag-modifiers/0.1`, scope `cinder`) and an optional display-only **`implementation`** (`automatic`, `informational`, `gm_resolved`) (0.41.0; schema in [`docs/modifiers-schema.md`](../../docs/modifiers-schema.md)): Manager checks the shape and asks the scope's module (Ashen Gate | Cinders) to check each modifier; without it they import with a warning. Manager never applies a modifier. Route records (0.27.0; needs a Locations with route import, i.e. 1.10.0–1.18.0 under the old numbering or 0.18.0+ — Manager checks the API, not the number; schema in `docs/routes-schema.md`) go to Locations after the locations they join; re-import never changes a route's discovery state. **Shop, Service and MerchantList** records (0.44.0, Utilities 0.21.0+; schema in [`docs/shop-schema.md`](../../docs/shop-schema.md)) go to Utilities (`api.shops.importShops`) after the package's Items, in the same run; without Utilities 0.21.0 they are listed as "Needs Utilities 0.21.0". Re-import never changes a shop's stock left, coins, sales or who it is shown to, and merchant lists come in hidden. Updates are field-wise and respect local edits. Item records can carry their **Active Effects** and the Hub companion-role flag (0.37.0; format in [`docs/item-effects-schema.md`](../../docs/item-effects-schema.md)): each effect has a permanent `eff_id`; re-import creates new effects, updates Manager-made ones field-wise (keeping GM edits), never deletes one and never touches hand-made effects. An opt-in **Update existing Actors** option changes only the package's own definition (name, image, defined token settings, package items) after a separate confirmation and a downloaded backup. A results panel keeps what was created, updated, kept or failed, and where to find it. Sample files are under GM Setup → Developer Tools. A **ZIP** can hold one Manager package (imported as before) or several import files — Manager packages plus Quest, Skill Tree, Strain config, Headquarters and Factions files: a **ZIP contents** list shows each file's type, record count and status; untick what you don't want, then each file goes through the same preview and Apply in turn (Manager packages first), with its own result. Ids already in an earlier file of the ZIP are reported and left out, never overwritten.
- **Icons** (0.47.0): a record may leave out `foundry.data.img`. A record with no icon or a placeholder one (blank, Foundry's default bag / mystery man / d20 / dice art, dnd5e's default item art, Manager's generic `assets/icons/*.svg`, or a local file that answers 404) gets a fitting icon from Foundry's icon library (core `icons/`, and `systems/dnd5e/icons` when readable), chosen from its name, kind and tags with the word list in `scripts/icon-keywords.js`; the preview's Icon column shows each pick with **Change…**. Authored icons (repeated generic ones included), remote URLs and `assets/` / `worlds/` paths are never replaced. On re-import an icon is filled only when the world copy still has a placeholder, or Manager picked it before (`flags.ashen-gate-manager.iconSource` `smart` or `fallback` and `iconPath` equal to the icon) and **Re-pick smart icons** is ticked; an icon the GM set is never changed. **Items → Checks → Improve icons** does the same for world Items and Actors, with backup and one-step Undo.
- **Items** (0.36.0; sub-tabs since 0.46.0): **Browse**, **Records**, **Folders**, **Core links**, **Checks** and **Export**. On Browse, Records, Folders and Core links one toolbar holds the search box and **Filters (n)**, which opens a second row; the filters are kept as you move between those sub-tabs: search, source (World or one compendium), type, origin (Ashen Gate, Core 2024, Core 2014, DDB / Plutonium, Homebrew), rarity (shown in the shared rarity colours, CSS variables `--ag-rarity-common` … `--ag-rarity-artifact`), folder (with its sub-folders) and *Has core_ref*. Origin is read from importer data: Manager's source flag, `flags.ddbimporter` or `flags.plutonium`, then a core source book (2024 or 2014 PHB/DMG/MM, SRD 5.1/5.2) or a dnd5e system pack (or a copy from one); everything else is Homebrew. Since 0.38.1 dnd5e's default `system.source.rules` on a hand-made item is not counted as core. The old tab ids `browse`, `library`, `organize` and `corelinks` open the matching sub-tab. Lists show 100 rows per page, so a world with thousands of items stays responsive.
- **Browse** (Items sub-tab; its facets sit in the Filters row): one read-only, GM-only search over world Actors, Items and Journals (and pages), the Ashen Gate records other modules expose (Locations and routes, Quest Log, Renown factions and **deities**, Skill Trees and perks, Headquarters facilities, Profession Ledger materials), Manager's own **NPC Codex**, and compendium indexes after *Load compendiums*. Type words or prefixes (`id:DEITY-`, `type:deity`, `type:npc-codex`, `tag:`, `status:`, `tier:major`); filter, group and pick Ashen Gate / Non-Ashen Gate / All. The same canonical id is one row listing every place it was found (an NPC Actor and its Codex entry are one row). Deities (Renown 0.11.0+, `api.getDeities()`) show tier, domain, discovery, status and visibility, with title, portfolio and related deities in the details; Open shows Renown's Pantheon at that deity. Codex rows show who knows the NPC, how many fields are revealed and how many links; Open jumps to the NPC Codex tab at that NPC. Without Renown there are simply no deity rows. Nothing in Browse writes.
- **Records** (was Library): a list of managed world documents (shared search and filters, system chips, more filters; grouped by system) with a detail pane beside it. **Check library** is under Checks and export under Export; **Adopt and tag** is in GM Setup → Developer Tools. Tick records and use **Actions** to export local edits, replace from loaded JSON, archive / restore, copy to a staging compendium or delete archived records (asks twice and names them). In short: browse managed world documents, check the library, export local edits, archive / restore, copy to a staging compendium and adopt existing world Items. **Export Ashen Gate data** saves one JSON file (everything, or only what changed since the last export) of tagged world documents plus the definitions the other modules expose.
- **My Appearance** (header button): your own skin and size; both save with *Save My Appearance*. The world default skin is set in GM Setup → General.
- **Modules:** which Ashen Gate modules are installed and active, with shortcuts to open them; since 0.38.0 each card shows whether it is visible to players, with **Reveal to players** / **Hide from players** (for modules that support Player Access), plus **Refresh** and **Hide all**. Since 0.46.0 General Manager has a card too, for its player NPC Codex (`api.playerAccess`, the same `codexPlayerAccess` setting as before); Open on it goes to the NPC Codex tab.
- **Item preview:** picking an Item in Items → Browse or Records shows dnd5e's own item card with its location (world/compendium, folder path, uuid) and key attributes below.
- **Scenes** (GM only; layers since 0.35.0): changes the lighting, weather and fog colours of the current scene (or a chosen one) using core Foundry only. Sub-tabs switch between **Live**, **Moods & layers** and **Export & import**; editing a preset replaces the list until you go back. Pick one **mood** (Day, Twilight, Windy, Storm, Night, or your own) and stack **layers** on it (Mist, Rain, Snow, Cold night, Blood moon, Hearth glow, Pitch black, Bright moon, or your own). Removing a layer puts back only the fields it changed, and keeps any you changed since. **Back to normal** undoes them all. **Fine-tune** has a slider for every supported field; it is a draft until *Apply to scene*, and *Save as layer/mood* makes it reusable. Optional darkness fade (Transition), per-scene favourites, and an export/import moods file: [`docs/scene-moods-schema.md`](../../docs/scene-moods-schema.md). API: `api.scenes`.
- **NPC Codex** (0.33.0; its own tab since 0.46.0): every imported NPC record. The detail has sub-tabs **Reveals** (per-field Hidden / Party / specific Characters; these apply at once), **Notes & links** (saved with Save Changes) and **Player preview**. GM-only fields (portrayal, session role, stat block, GM notes) never reach players. Players get a read-only codex of what is revealed to them (Modules tab → the General Manager (NPC Codex) card, *Reveal to players*; then Configure Settings → *Open NPC Codex*, which players see only while the Codex is shared; since 0.45.0 nothing else of General Manager shows in players' Game Settings, and players open My Appearance from Utilities' Appearance button). Export and restore of reveals; `api.codex` (including `mount(element)` for a Character Hub tab). Record schema: [`docs/npc-codex-schema.md`](../../docs/npc-codex-schema.md).
- **Folders** (was Organize; folds since 0.46.0: *Clean compendiums*, *Organize a selection*, *Rules & protected folders*, *History*): files world (or unlocked world-compendium) Items, Actors and Journals into a rule-based folder tree; Preview, Apply, Undo; protected folders and Keep here. Works on the Source picked above (World when All sources), either everything there or **this selection or folder**: what the filters above match, e.g. Origin DDB / Plutonium, or one Folder and its sub-folders. The read-only housekeeping report is under Checks. **Clean compendiums** (0.36.0) is one button that does this for the world sidebar and every unlocked world compendium at once (Refile everything, ignoring the filters): preview every move, untick any, Apply; locked, module and system compendiums are listed as skipped. Default rules (0.30.0): Ashen Gate records go under `Ashen Gate/…`; non-Ashen-Gate Items that are **source-tagged** (since 0.38.1 this needs positive evidence: imported by Plutonium, a core `system.source.book` (2024 PHB'24, DMG'24, MM'24, SRD 5.2, or, since 0.31.0, 2014 PHB, DMG, MM, SRD 5.1), or a dnd5e system compendium; a copy from a dnd5e compendium or a D&D Beyond import with no core book is weak evidence, left unticked in Clean compendiums) go under `Core 5.5e/…`; non-Ashen-Gate Items with no source, only dnd5e's default `system.source.rules`, or a third-party or homebrew source, go under `Homebrew/…` with the same sub-folders (spells by level, magic items by rarity, weapons, armor, …). Saved custom rules are kept as they are. Rule format: [`docs/organize-rules.md`](../../docs/organize-rules.md).
- **Core links** (was Core Links): links Ashen Gate world Items that carry `core_ref` to 2024 (5.5e) core items (world Items with 2024 core evidence, e.g. imported by Plutonium or a 2024 core book, never a hand-made item with only dnd5e's default rules: a narrower test than Organize's, which also counts 2014 core as Core; world compendiums; GM core sources; dnd5e 2024 packs; never 2014 content) and, for exact matches, adopts the core item's image and data while keeping the Ashen Gate name and id. See *Core references* below. With filters on, only the scanned items they match are shown, and Apply and Download backup use only those ticked rows.
- **GM Setup:** sub-tabs **General** (the world default skin, as cards), **Core sources** (which compendiums and folders count as core sources for Core links) and **Developer Tools** (example package, sample files, Adopt & tag). Settings save together with *Save Changes*, and an unsaved change survives switching tabs; closing the window asks first.
- **Import history** (Import sub-tab; was the History tab): recent import operations and downloadable snapshots taken before updates, archives and deletes. There is no automatic undo; a snapshot is not a world backup.

## Core references (`core_ref`)

An Ashen Gate Item or Material record that should become a 2024 core item carries `core_ref` in its source record (next to `id`, `entity_type` and the other definition fields, not inside `foundry.data`):

```json
"core_ref": {"name": "Potion of Healing", "source": "DMG'24", "type": "consumable", "rarity": "common"}
```

- `name` (required): the core item's name as it appears in the 2024 books / Plutonium / dnd5e packs. A plain string (`"core_ref": "Potion of Healing"`) also works.
- `source` (optional): the book, e.g. `PHB'24`, `DMG'24`, `MM'24` (`XPHB`, `XDMG`, `XMM` and `SRD 5.2` are understood too). When given, a different book makes the match MEDIUM.
- `type` (optional): the Foundry Item type (`weapon`, `equipment`, `consumable`, `tool`, `loot`, `container`, …). Defaults to the record's own Foundry type.
- `rarity` (optional): dnd5e rarity (`common`, `uncommon`, `rare`, `veryRare`, `legendary`, `artifact`).

Records without `core_ref` are never linked. Linking keeps the Ashen Gate name and id; the link is stored in `flags.ashen-gate-manager.coreLink`.

## Relation to other modules

Manager owns source-definition import and shared appearance. Each specialist module owns its own state (Actor progression, Renown, Headquarters, Locations, Quests) and keeps working when Manager is missing or disabled; Manager feature-detects partners through their public APIs and never writes their state directly. Modules fall back to a default theme without Manager's appearance controller.

## Public API

`game.modules.get('ashen-gate-manager').api` (set on `ready`). "GM-only" below means the function itself refuses a player, not just the UI:

- `open()`: opens the Manager window (GM-only; a player gets a notice).
- `appearance`: `contract`, `listSkins`, `getState`, `applyTo(root)` (only for a detached root such as a pop-out or iframe: every window inside the page already follows `<html>` live, so calling it on a window's own content leaves a stale copy of the tokens), `subscribe(callback)`, `refresh`, `setWorldDefault(id)` (GM-only), `setUserOverride(id)` (the current user's own skin), `openMyAppearance()` (player-safe My Appearance window).
- `definitions` (read-only definition reader): `contract`, `getState`, `capabilities`, `resolve(id, opts)` and `list(opts)` (a player sees only records visible to them), `readSource(id, opts)` (GM-only; a player gets `not_found`), `audit()` and `validateReferences()` (GM-only, `forbidden` otherwise), `registerProvider(cfg)`, `loadCompendiums(packIds)` and `refreshCompendiums()` (GM-only, throw otherwise), `refresh`, `dispose`.
- `preSessionCheck()` (0.21.0): GM-only, read-only health report (module versions, GM storage, Player Access, test data, leak scan, migration, environment); resolves to `{rows, counts, summary, text, filename}`.
- `backup()` (0.21.0): GM-only "Back up before play": downloads the everything export as `AG_Backup_<date>.json`; it does not move the export snapshot.
- `coreLinks` (0.26.0, GM-only): `preview`, `apply({ids, linkOnly})`, `undoLast`, `history`, `describeSources`, `saveSources`. See *Core references* below.
- `organize` (0.25.0, GM-only; only a document's folder is written): `listSources`, `preview` and `apply` (`{source, types, mode, ids, folderId}`), `undoLast`, `history`, `getSchema`, `saveSchema(rules)`, `resetSchema`, `setFolderProtected(folder, value)`, `setKeepFolder(doc, value)`, `housekeeping` (read-only report), and Clean compendiums (0.36.0) `cleanPreview()` / `cleanApply({moves, signal, onProgress})` (0.45.0: writes 50 documents at a time and yields between them; an AbortSignal stops it between chunks, and what was written is in Undo). Rule format: [`docs/organize-rules.md`](../../docs/organize-rules.md).
- `browse` (0.24.0, GM-only, read-only All items index): `getIndex`, `search(options)`, `detail(key)`, `refresh`, `loadCompendiums`, `status`, `dragData(key)`, `open(key)`.
- `scenes` (0.22.0; layers 0.35.0; GM-only, a player gets `{ok: false, message}`): `listMoods`, `getState`, `applyMood`, `addLayer`, `removeEffect`, `restore` (Back to normal), `applyDraft`, `toggleFavourite`, `savePreset`, `removePreset`, `resetDefaults`, `exportPresets`, `previewImport`, `importPresets`.
- `codex` (0.33.0, NPC Codex): GM-only `list`, `get(id)`, `characters`, `setReveal(id, key, opts)`, `setDetails(id, patch)`, `previewAs(actorIds)`, `exportAll`; player-safe `forPlayer`, `playerAccessEnabled`, `openPlayerView`, `mount(element)` (a player gets only what is revealed to their characters, through the connected GM).
- `resolverBridge` (prototype adapter): `contract`, `audit(resolver)`, `auditPackage(records, resolver)`, `renderMarkers(text, resolver)`; all GM-only (`forbidden` otherwise) and need a caller-supplied resolver.
- `playerAccess`: `contract` (`ag-player-access/1`), `getState()`; Manager is always GM-only and not configurable.

## Install

Foundry or The Forge: **Add-on Modules → Install Module → Manifest URL**, paste

`https://raw.githubusercontent.com/robbmcgaw/ashen-gate-foundry/main/modules/ashen-gate-manager/module.json`

and Install. Updates arrive through Check for Updates / Forge's update button. Every version is also on the [GitHub Releases](https://github.com/robbmcgaw/ashen-gate-foundry/releases) page (tag `ashen-gate-manager-v<version>`) for manual install or rollback. Change history is in [CHANGELOG.md](CHANGELOG.md).
