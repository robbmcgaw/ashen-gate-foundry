# Ashen Gate | General Manager

Module ID `ashen-gate-manager` · Foundry V14 · dnd5e. The GM hub: one importer for Ashen Gate data, a library of what was imported, shared appearance settings (header dropdown) and Player Access on the Modules tab. It is GM-only; the other modules work without it. Open it from **Items sidebar → General Manager** (GM only).

## Tabs

- **Import:** load an `ag-foundry-import` JSON package, preview every record as create, update or skip, pick what to apply and apply it. It creates world Items, Journals, Actors, Roll Tables and Macros (imported Macros are never run), matched by permanent id, never by name. Quest, Skill Tree, Headquarters facility, Factions and Location records are recognised by shape and handed to those modules when they are active (otherwise skipped with a reason). Cinder definitions, powers and Backfire tables (0.39.0; schema in [`docs/cinder-strain-schema.md`](../../docs/cinder-strain-schema.md)) import as documents and their `cinder` / `power` / `backfire` blocks are checked by Skill Trees 0.16.0+; a **Strain config** file (`ag-strain-config/0.1`) is handed to Skill Trees. Importing never creates or changes Cinder instances, bearers, progress or Strain. Route records (0.27.0, Locations 1.10.0+; schema in `docs/routes-schema.md`) go to Locations after the locations they join; re-import never changes a route's discovery state. Updates are field-wise and respect local edits. Item records can carry their **Active Effects** and the Hub companion-role flag (0.37.0; format in [`docs/item-effects-schema.md`](../../docs/item-effects-schema.md)): each effect has a permanent `eff_id`; re-import creates new effects, updates Manager-made ones field-wise (keeping GM edits), never deletes one and never touches hand-made effects. An opt-in **Update existing Actors** option changes only the package's own definition (name, image, defined token settings, package items) after a separate confirmation and a downloaded backup. A results panel keeps what was created, updated, kept or failed, and where to find it. Sample files are under Import → Advanced / sample files. A **ZIP** can hold one Manager package (imported as before) or several import files — Manager packages plus Quest, Skill Tree, Strain config, Headquarters and Factions files: a **ZIP contents** list shows each file's type, record count and status; untick what you don't want, then each file goes through the same preview and Apply in turn (Manager packages first), with its own result. Ids already in an earlier file of the ZIP are reported and left out, never overwritten.
- **Items** (0.36.0): one tab with a Library-style icon rail: **All items**, **Ashen Gate records**, **Folders**, **Core links**, **Checks**, plus **Export and backup**, **Adopt and tag** and **NPC Codex**. Filters at the top are kept as you move along the rail: search, source (World or one compendium), type, origin (Ashen Gate, Core 2024, Core 2014, DDB / Plutonium, Homebrew), rarity (shown in the shared rarity colours, CSS variables `--ag-rarity-common` … `--ag-rarity-artifact`), folder (with its sub-folders) and *Has core_ref*. Origin is read from importer data: Manager's source flag, `flags.ddbimporter` or `flags.plutonium`, then a core source book (2024 or 2014 PHB/DMG/MM, SRD 5.1/5.2) or a dnd5e system pack (or a copy from one); everything else is Homebrew. Since 0.38.1 dnd5e's default `system.source.rules` on a hand-made item is not counted as core. The old tab ids `browse`, `library`, `organize` and `corelinks` open the matching rail entry. Lists show 100 rows per page, so a world with thousands of items stays responsive.
- **All items** (was Browse): one read-only, GM-only search over world Actors, Items and Journals (and pages), the Ashen Gate records other modules expose (Locations and routes, Quest Log, Renown factions and **deities**, Skill Trees and perks, Headquarters facilities, Profession Ledger materials), Manager's own **NPC Codex**, and compendium indexes after *Load compendiums*. Type words or prefixes (`id:DEITY-`, `type:deity`, `type:npc-codex`, `tag:`, `status:`, `tier:major`); filter, group and pick Ashen Gate / Non-Ashen Gate / All. The same canonical id is one row listing every place it was found (an NPC Actor and its Codex entry are one row). Deities (Renown 0.11.0+, `api.getDeities()`) show tier, domain, discovery, status and visibility, with title, portfolio and related deities in the details; Open shows Renown's Pantheon at that deity. Codex rows show who knows the NPC, how many fields are revealed and how many links; Open jumps to Items → NPC Codex at that NPC. Without Renown there are simply no deity rows. Nothing in Browse writes.
- **Ashen Gate records** (was Library): a list of managed world documents (shared search and filters, system chips, more filters; grouped by system) with a detail pane beside it. **Check library** is under Checks; **Export and backup** and **Adopt and tag** have their own rail entries. Tick records and use **Actions** to export local edits, replace from loaded JSON, archive / restore, copy to a staging compendium or delete archived records (asks twice and names them). In short: browse managed world documents, check the library, export local edits, archive / restore, copy to a staging compendium and adopt existing world Items. **Export Ashen Gate data** saves one JSON file (everything, or only what changed since the last export) of tagged world documents plus the definitions the other modules expose.
- **Appearance** (dropdown in the top bar, next to Help): the world default skin and **Open My Appearance** for per-user choice.
- **Modules:** which Ashen Gate modules are installed and active, with shortcuts to open them; since 0.38.0 each card shows whether it is visible to players, with **Reveal to players** / **Hide from players** (for modules that support Player Access), plus **Refresh** and **Hide all**.
- **Item preview:** picking an Item in Items → All items or Ashen Gate records shows dnd5e's own item card with its location (world/compendium, folder path, uuid) and key attributes below.
- **Scenes** (GM only; layers since 0.35.0): changes the lighting, weather and fog colours of the current scene (or a chosen one) using core Foundry only. The rail switches between **Live**, **Moods & layers** and **Export & import**. Pick one **mood** (Day, Twilight, Windy, Storm, Night, or your own) and stack **layers** on it (Mist, Rain, Snow, Cold night, Blood moon, Hearth glow, Pitch black, Bright moon, or your own). Removing a layer puts back only the fields it changed, and keeps any you changed since. **Back to normal** undoes them all. **Fine-tune** has a slider for every supported field; it is a draft until *Apply to scene*, and *Save as layer/mood* makes it reusable. Optional darkness fade (Transition), per-scene favourites, and an export/import moods file: [`docs/scene-moods-schema.md`](../../docs/scene-moods-schema.md). API: `api.scenes`.
- **NPC Codex** (0.33.0, Items → NPC Codex): every imported NPC record with per-field reveals (Hidden / Party / specific Characters). GM-only fields (portrayal, session role, stat block, GM notes) never reach players. Players get a read-only codex of what is revealed to them (GM Setup → *Players can open the NPC Codex*; then Configure Settings → *Open NPC Codex*). Export and restore of reveals; `api.codex` (including `mount(element)` for a Character Hub tab). Record schema: [`docs/npc-codex-schema.md`](../../docs/npc-codex-schema.md).
- **Folders** (was Organize): files world (or unlocked world-compendium) Items, Actors and Journals into a rule-based folder tree; Preview, Apply, Undo; protected folders and Keep here. Works on the Source picked above (World when All sources), either everything there or **this selection or folder**: what the filters above match, e.g. Origin DDB / Plutonium, or one Folder and its sub-folders. The read-only housekeeping report is under Checks. **Clean compendiums** (0.36.0) is one button that does this for the world sidebar and every unlocked world compendium at once (Refile everything, ignoring the filters): preview every move, untick any, Commit; locked, module and system compendiums are listed as skipped. Default rules (0.30.0): Ashen Gate records go under `Ashen Gate/…`; non-Ashen-Gate Items that are **source-tagged** (imported by Plutonium, or `system.source` rules/book set to 2024: PHB'24, DMG'24, MM'24, SRD 5.2, or, since 0.31.0, to 2014 core: rules `2014`, PHB, DMG, MM, SRD 5.1) go under `Core 5.5e/…`; non-Ashen-Gate Items with no source, or a third-party or homebrew source, go under `Homebrew/…` with the same sub-folders (spells by level, magic items by rarity, weapons, armor, …). Saved custom rules are kept as they are. Rule format: [`docs/organize-rules.md`](../../docs/organize-rules.md).
- **Core links** (was Core Links): links Ashen Gate world Items that carry `core_ref` to 2024 (5.5e) core items (world Items imported by Plutonium or marked 2024, a narrower test than Organize's, which also counts 2014 core as Core; world compendiums; GM core sources; dnd5e 2024 packs; never 2014 content) and, for exact matches, adopts the core item's image and data while keeping the Ashen Gate name and id. See *Core references* below. With filters on, only the scanned items they match are shown, and Apply and Download backup use only those ticked rows.
- **GM Setup:** which compendiums and folders count as core sources for Core Links.
- **History:** recent import operations and downloadable snapshots taken before updates, archives and deletes. There is no automatic undo; a snapshot is not a world backup.

## Core references (`core_ref`)

An Ashen Gate Item or Material record that should become a 2024 core item carries `core_ref` in its source record (next to `id`, `entity_type` and the other definition fields, not inside `foundry.data`):

```json
"core_ref": {"name": "Potion of Healing", "source": "DMG'24", "type": "consumable", "rarity": "common"}
```

- `name` (required): the core item's name as it appears in the 2024 books / Plutonium / dnd5e packs. A plain string (`"core_ref": "Potion of Healing"`) also works.
- `source` (optional): the book, e.g. `PHB'24`, `DMG'24`, `MM'24` (`XPHB`, `XDMG`, `XMM` and `SRD 5.2` are understood too). When given, a different book makes the match MEDIUM.
- `type` (optional): the Foundry Item type (`weapon`, `equipment`, `consumable`, `tool`, `loot`, `container`, …). Defaults to the record's own Foundry type.
- `rarity` (optional): dnd5e rarity (`common`, `uncommon`, `rare`, `veryRare`, `legendary`, `artifact`).

Records without `core_ref` are never linked. Linking keeps the Ashen Gate name and id; the link is stored in `flags.ashen-gate-manager.coreLink`.

## Relation to other modules

Manager owns source-definition import and shared appearance. Each specialist module owns its own state (Actor progression, Renown, Headquarters, Locations, Quests) and keeps working when Manager is missing or disabled; Manager feature-detects partners through their public APIs and never writes their state directly. Modules fall back to a default theme without Manager's appearance controller.

## Public API

`game.modules.get('ashen-gate-manager').api`: `open`, `appearance` (`listSkins`, `getState`, `applyTo`, `subscribe`, `refresh`, `setWorldDefault`, `setUserOverride`, `openMyAppearance`), `definitions` (read-only definition reader: `readSource`, `resolve`, `list`, `audit`, `validateReferences`, `registerProvider`, `loadCompendiums`, `refreshCompendiums`, …), `resolverBridge` and `playerAccess` (GM-only, not configurable).

## Install

Foundry or The Forge: **Add-on Modules → Install Module → Manifest URL**, paste

`https://raw.githubusercontent.com/robbmcgaw/ashen-gate-foundry/main/modules/ashen-gate-manager/module.json`

and Install. Updates arrive through Check for Updates / Forge's update button. Every version is also on the [GitHub Releases](https://github.com/robbmcgaw/ashen-gate-foundry/releases) page (tag `ashen-gate-manager-v<version>`) for manual install or rollback. Change history is in [CHANGELOG.md](CHANGELOG.md).
