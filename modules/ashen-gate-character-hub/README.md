# Ashen Gate | Character Hub

An alternative character sheet for dnd5e 6 on Foundry V14. It shows and changes the **real** Actor: there is no separate character data, so the standard dnd5e sheet and the Hub always agree. Rolls, item use, rests, advancement and item configuration go through dnd5e's own dialogs.

## Open it
Open a character → the sheet's title-bar menu (**Sheet** / gear) → choose **Ashen Gate Character Hub**. Switch back the same way. It is never the default unless you pick it. **Open native sheet** in the header's **⋯** menu opens the standard dnd5e sheet at any time. **Level up** (an icon button in the header beside Compact since 0.46.0; in the ⋯ menu from 0.34.0, under the name before) starts dnd5e's own level-up, or adds a class through dnd5e's class browser (it adds no rules of its own). Each level-up keeps a GM-only copy of the character as it was, named `<name> - level X`, in the Actor folder Ashen Gate / Level backups.

## What it does
Layout: the character on the left, the chosen section in the middle (only it scrolls), a rail of sections down the right edge (icon and name; icons only between about 900 and 1000 px wide; arrow keys move between them), and the Ashen Gate quick bar along the bottom edge. Opens at 1240 × 800; under about 900 px wide the tabs come first as one slim row (small icon and name side by side, sticky at the top, scrolling sideways when they do not fit), then the character, then the section; those scroll together while Mastery & marks, the Ashen Gate quick bar and the quick bar drawer stay pinned along the bottom (0.41.0). The character shows by default there; **Hide character** folds it to its Cinders, star, HP and AC and **Show character** opens it again (remembered per user in the browser, kit `uiState`). The header holds only **Compact** / **Full**, the **⋯** menu (Appearance…, Pop out, NPC Codex, Open native sheet) and the version with Help (0.33.0). The window is always opaque (the 0.10.0-0.28.x opacity slider was removed in 0.29.0). **Compact** in the header shrinks it to one narrow column (per user, client setting `compactMode`): the art with its equipment slots, initiative / speed / proficiency on one line, HP with hit dice, rests, exhaustion and Strain, the six abilities with their saves and the conditions (0.32.0; the column scrolls inside itself), with Mastery & marks and the quick bar frozen at the bottom, with an optional see-through background (60-100 %) in its **⋯ → Appearance…** menu; **Pop out** (in the ⋯ menu) moves it into its own browser window with Foundry V14's own ApplicationV2 detach. Every section heading (and each inventory container) folds open and closed; which ones are folded is remembered per user on that computer (client setting `collapsedSections`).
- Header name and title (0.40.0): the character's title shows beside the name (smaller, italic, muted; plain text, up to 60 characters, stored as the Actor flag `flags.ashen-gate-character-hub.title` because dnd5e 6.0.6 has no title field). Owners and the GM change the name (`actor.name`) and the title with the pen button beside the name or **Edit name and title…** in the **⋯** menu; Save writes only what changed. Refused for observers, limited viewers and level backup copies (`name-title.mjs`).
- Left (0.34.0): one name row (the name; a chip per class with its level, each subclass after its class, species and background, each with the item's icon, click to open; the Cinder chips; the inspiration star last), then the portrait with AC and the equipment slots around it (rings and trinkets right under the art), initiative roll, speed, proficiency, HP bar, six abilities (check and save rolls), resources. Compact shows subclass, species and background as icons only (named in the tooltip).
- Bottom (0.34.0): **Mastery & marks**, then **Conditions** (Self / Target, a dnd5e condition that is also a Foundry status effect, Apply; chips with ✕ for the character's and the current targets' conditions; real status effects via `Actor#toggleStatusEffect`; players follow Utilities' `api.conditions` rules (`canApply` / `canRemove`, then `apply` / `remove`), or without Utilities only their own characters; tokens not linked to a character are left to the GM), then the bar with the Ashen Gate buttons and the **Quick bar** toggle; the quick bar opens as a drawer under it and the window grows by its height (not in a popped-out window).
- HP bar: "X / X HP"; the fill is green at 70% of max HP and up, yellow from 30%, red below. Since 0.39.0 each effect has its own part of the bar, side by side: current HP, then temp HP (silver stripes, "(+X TEMP)"), then the empty part, then at the end a raised max (blue outline, "(+X MAX)", filled from the left when HP is above normal max) or a reduced max (dark green cross-hatching, "(−X MAX)"). The bar is normal max + raised max + temp HP; a thin dark line separates the parts, and the tooltip says it all in words. Double-click the bar to set current, temp and max adjustment; right-click opens dnd5e's Hit Points settings. The − / amount / + controls damage (temp HP first) or heal. Hit dice with Short/Long Rest and exhaustion sit right under the bar.
- **Right-click to configure:** AC, initiative, speed, HP, hit dice, death saves, each ability, skill and save, senses and proficiencies (armor, weapons, tools, languages) open dnd5e's own configuration window for that value, the same one the standard sheet opens. Only for users who can edit the character (owner or GM), as on the standard sheet. **Configure…** in the header's **⋯** menu (0.34.0; under the name in 0.33.0) lists the same windows for keyboard users; saving throws are rolled from the ability tiles (the Overview's separate Saving Throws list was removed in 0.33.0). Speed's window has walk, burrow, climb, fly, jump, swim, hover and units (dnd5e 6 movement data); non-zero speeds and hover show on the Speed tile.
- Equipment slots (display only, no slot rules): head, neck, back, body, hands; main hand, off hand, waist, feet, bracers; ring, ring and three trinkets. Empty slots show an icon (or a word where no icon fits), set per slot in the `SLOT_PLACEHOLDERS` table in `scripts/constants.mjs` (Font Awesome class, Foundry image path such as `icons/equipment/...`, or text). Equipped items show a coloured border by dnd5e rarity (common white, uncommon green, rare blue, very rare purple, legendary orange, artifact red; CSS variables `--ag-rarity-<key>`). Click opens the item, right-click unequips, ⋯ opens Use, Attune, Swap (hands, rings), Move to party stash, Move to…; an empty slot offers Equip… with carried items that fit. **Other equipped** (folding list under the rings and trinkets) shows every equipped item not in a slot. Equipping an item that needs attunement asks first; at the limit it lists attuned items to unattune.
- Overview: skills (rolls, proficiency markers, passive) on the left; saving throws, passives and senses, proficiencies on the right; striped rows. **Professions** (0.30.0) under Proficiencies: each profession the character knows as an icon and "Name - Tier - Level n" (0.34.0; icons from `PROFESSION_ICONS` in `views.mjs`, a toolbox for any other), from the Profession Ledger's `getProfessions(actor)` (feature-detected; `tier` when the Ledger gives it); click the box to show Ashen Gate → Professions. No box without the Ledger (or one without `getProfessions`), when Professions is hidden from players (the GM's switch, or the Ledger's Player Access off), or when the Ledger refuses the user.

## Biography (0.38.0)
**Journey → Biography** (kit sub-tabs Journey | Biography; the choice is remembered per user in the browser, kit `uiState` key `journeyView`) mirrors the dnd5e character sheet's Biography page and reads and writes the Actor's own dnd5e 6.0.6 fields: `system.details.biography.value` and `.public` (HTML), `trait`, `ideal`, `bond`, `flaw`, `appearance` (plain text) and `age`, `height`, `weight`, `eyes`, `skin`, `hair`, `gender`, `faith`, `alignment` (plain text). A field shows only when the Actor's data has it.
- Owner and GM: everything, editable. The HTML fields use Foundry's `<prose-mirror>` element when it is defined (otherwise read-only with **Open native sheet to edit formatting**). **Save Changes** / **Cancel** sit in a footer pinned to the pane; **Unsaved changes** shows while there are edits; tab / sub-tab switches and closing ask first (kit `guardDirty`); a redraw keeps the typed text (the draft lives on the open sheet).
- Observer: `biography.public`, `appearance` and the characteristics only (rich text enriched without secrets). Limited: the Hub's limited view (name and portrait) as before.
- `updateBiography` (scripts/biography.mjs) refuses non-owners and writes only the fields whose value differs from the stored one, in one `actor.update`.

## Journey (0.20.0)
A per-character log of accomplishments, newest first, in the **Journey** tab (the **Journey** sub-tab since 0.38.0). It records **from now on**; nothing earlier is back-filled.
- **Automatic entries**, only from existing events and public APIs:
  - **Level-ups:** dnd5e's character level (`system.details.level`) rising.
  - **Renown tier changes:** a character's personal rank and the party's rank with each faction. **Piety rank changes** (0.58.1) are their own entry type, "Piety": its rank with each deity (older deity entries saved as "Renown" read Piety too). Read through Renown's public `getFactions()` / `getPantheon()` as the owning player sees them, so they are recorded while that player is online and Renown's Player Access is on. The GM's view has no standings.
  - **Quests completed:** Quest Log's GM `listQuests()` / `getGMState()`. A personal quest is logged for its character; a party quest for every player character.
  - **Quest rewards (items and coins, 0.25.0):** recorded when Quest Log grants a reward, through `api.journey.recordReward(actor, {questId, questName, coins, text, items, grantId})` (GM only; refused for players in the API). `items` is optional, up to 50 of `{name, img, quantity, itemId}` (anything else is dropped); `grantId` is optional (`A-Z a-z 0-9 _ -`, up to 40). - **The GM** sees every character's journey (a character picker) and can:

  - Visible entries: `flags.ashen-gate-character-hub.journey` on the Actor (`{v, entries, seen}`).

- **Writers:** one client writes for each character, the first active GM, else the character's first active owner. Renown entries are written by the owner's client.

## Companions
A **Mount** box (larger, first) and up to three **Pet** boxes. In a narrow window they stack, mount first.

- **A pet or mount is a world Actor** (an NPC with stats, so it can be used in battle). Link it by dropping it from the Actors sidebar onto a box, by typing part of its name in **Find an Actor by name…** and pressing Enter, or from **or link a world Actor…**. Players need at least Observer permission on it (the GM must share it first), compendium Actors must be imported first, and an Actor that was linked and is no longer shared stays listed (removable) but shows nothing from it.
- **Owned Actors are listed for you (0.49.0).** Each pet and mount dropdown also lists, under **Yours to use**, the NPC Actors the character's player **owns** (Owner permission only), each with a Pet or Mount tag. Choosing one links it and makes it active, so a player needs no drop or search; the manual routes remain for Actors that are not eligible or have no kind. The GM awards a companion by giving the player Owner on the Actor. Never listed: the character itself, player characters and other non-NPC Actors, level backups, compendium Actors, Actors the player cannot see, a pet already active in another box. An Actor counts as owned when at least one non-GM user who owns the character also owns it (a GM-run character uses the viewing user's own permission; a GM viewing one gets no automatic list). Nothing is removed automatically: if ownership is taken away, a linked companion stays linked with a "No longer owned" note until the player clears it.
- **What kind an Actor is.** In order: the GM's **Companion type** (`flags.ashen-gate-character-hub.companionType`: `pet`, `mount`, `either` or `none`, set in GM Setup → Companion types; Automatic clears it); the import id Manager stamps (`flags.ashen-gate-manager.source.sourceId`): `CRE-MOUNT-` is a mount, `CRE-PET-` a pet, `NPC-` (a person) is none; any other `CRE-` id and any Actor with no id go by size (`system.traits.size`): tiny, sm, med are pets; lg, huge, grg are mounts. Either lists in both boxes, none in neither. The GM Setup card shows the effective kind and why, e.g. "Mount (Large)". Only the GM can set it (enforced in the data layer). A player can link from the list only an Actor they own whose kind fits the box.
- **Many linked, a few active.** A character may link many pets and many mounts. One mount and up to three pets are active at once. Each pet box has an **Active pet** dropdown that lists the linked pets not active in another box, plus an empty choice that clears the box; a pet is active in one box only. **Open sheet** opens the Actor's sheet if you may observe it. Each box shows a small portrait (neutral icon without art), the name, and a one-line strip of the Actor's own AC, HP and speed when present.
- **Pet slots.** How many pet boxes a character has (0 to 3) is set by the GM in GM Setup → Pet slots: a default (3) and a per-character override. Limits are enforced in the data layer. Lowering the number never removes a pet: empty extra boxes are hidden and a pet already in an extra box stays shown until the player clears it. Another module can add slots with `registerPetSlotSource`; the total is never more than 3.
- **Your own name and description.** **Edit name…** on a box lets the character's owner or the GM give the companion a name (up to 60 characters) and a description (up to 500), plain text. They are stored on the character, not on the Actor, so players need no ownership of the Actor. An empty name falls back to the Actor's own; when the names differ the Actor's name shows in small text. The editor keeps unsaved typing across redraws and asks before Cancel discards it.
- **Sockets.** Each pet has 2 (Head, Body); the Mount has 5 (Saddle and four Tack). A socket holds one Item and an Item sits in one socket of one companion at a time. Gear is an ordinary Item on the character with the existing roles `pet-clothing` / `mount-gear` (or unmarked non-feature loot and equipment). Drop it on a socket, or on a box for the first free socket of its type (items from elsewhere are copied onto the character, following the shared item-drop standard, `scripts/ag-item-drop.mjs` and `docs/item-drop-standard.md`); an empty socket's **Add gear…** list (only items that fit it) is the keyboard route. **Remove** takes the item out of the socket and leaves it on the character.
- **Which gear fits which socket.** An item can name its slot with `flags.ashen-gate-character-hub.companion.slot` (docs/companion-items-schema.md): `saddle` or `tack` for mount gear, `head` or `body` for pet clothing. A classified item fits only that socket type and a wrong drop is refused. An item with no slot (older data) fits any socket of its kind, so nothing breaks before content is classified. The slot only controls fit; it carries no other mechanics.
- **Gear stays with its companion.** Sockets and perks are stored per companion Actor, so switching the active pet or mount hides that gear and switching back shows it again. Removing a companion from the character forgets its sockets and name (the Items stay).
- **Bonuses.** Each socket row lists everything the item gives and each box's stats area totals gear and perks from the items' own Active Effects and armour value. Display only: the Hub applies nothing to the character or the Actor. Perk Items (`mount-perk` / `pet-perk`) are listed for the active companion. A tier (`flags.ashen-gate-character-hub.companion.tier`, display only) shows beside the name when an item has one.
- **Older companions.** Pets and mounts saved as Items before 0.47.0 are kept and listed read-only in a fold; they are not deleted or converted. Actor links from before 0.47.0 are carried over by the migration (the old `companions` list itself is never changed), including names and descriptions typed then.

Permissions are checked in the data layer: the character's owner or the GM may change companions, and players are refused while the GM hides the Companions part. Only the GM can change pet slots and companion types. A level backup copy is never a target.

## Permissions
Owners and the GM can change and roll. Observers can look only (the actions refuse them too, not just the buttons). Limited viewers see portrait and name. Parts the GM hides from players are refused to players in the Hub's actions too (see Player visibility).

## Public API
`game.modules.get('ashen-gate-character-hub')?.api`
- `open(actor)` → opens the Hub for a character (`{ok, error?}`).
- `openNativeSheet(actor)` → opens dnd5e's standard character sheet.
- `companions(actor)` → `{mount, pets, petCap}` (read only). `mount` is the active mount (or null); `pets` lists every linked pet; each is `{itemId: null, actorUuid, name, actorName, description, active, perkItemIds, gearItemIds}`. `name` is the player's own name for it, falling back to the Actor's name; `actorName` is the Actor's; `description` is the player's text. `active` is true for a pet in any pet box. `petCap` is the character's number of pet slots (0 to 3). `petCapFor(actor)` still returns `Infinity` (linked pets are unlimited). `petSlotsFor(actor)` returns the number of pet slots.
- `eligibleCompanions(actor, kind)` → `[{actorUuid, name, kind, reason, linked}]` for `'pet'` or `'mount'` (read only, 0.49.0): the NPC Actors the character's player owners own whose effective kind fits, as the current user sees them. `companionKind(actor)` → `{kind: 'pet'|'mount'|'either'|'none', source, label}`.
- `registerPetSlotSource(id, fn)` / `unregisterPetSlotSource(id)`: `fn(actor)` returns a whole number of extra pet slots; the total for a character is never more than 3. A hook that throws is ignored. `unregisterPetSlotSource` returns whether the id was registered.
- `playerVisibility` (0.9.0):
  - `parts()` → `[{key, label, partner}]` (`partner` is the backing module id or null); `presets()` → `[{id, label}]` (`everything`, `core`).
  - `get()` → the stored switches as `{partKey: boolean}` (every part, missing = true).
  - `isShown(key)` → `true` when players see that part (the GM's switch and the partner's Player Access); `hiddenReason(key)` → the reason string, or `null`.
  - `canSee(key)` → `true` for the current user (always for the GM).
  - `set({partKey: boolean})` and `applyPreset(id)` → GM only, resolve to `{ok, result | error}`; unknown keys and non-booleans are refused.
- `nativeSheetAvailable()`, `sheetClass`, `version`.

## Level backups (0.27.0)
Each Hub level-up keeps a GM-only copy of the character as it was before, named `<name> - level X`, in the Actor folder **Ashen Gate / Level backups**. Delete old copies by hand. The copy keeps dnd5e data, items and effects; its live Ashen Gate flag scopes are removed (all `ashen-gate-*` except `ashen-gate-manager` source ids) so it is never a second bearer or progression. Cinder instance records stay in Cinders and are not touched. The removed flags are kept (0.28.0 Restore uses them):

```
flags['ashen-gate-character-hub'].levelBackup = {
  sourceId,        // the character's Actor id
  sourceName,      // its name at the time
  levelBefore,     // character level before the level-up
  classesBefore,   // [{id, name, identifier, levels}] before the level-up
  date,            // YYYY-MM-DD
  opId, by,        // request id (one copy per id) and the user who levelled
  archivedFlags: {
    actor:       {scope: flags},                     // the Actor's removed scopes
    items:       {itemId: {scope: flags}},           // each item's removed scopes
    effects:     {effectId: {scope: flags}},         // the Actor's effects
    itemEffects: {itemId: {effectId: {scope: flags}}} // effects on items
  }                // each key present only when something was removed; ids are the copy's (= the source's) ids
}
```
To restore, put each archived scope back on the document its id names and remove `levelBackup`.

### Restore (0.28.0, GM only)
**Restore backup…** in the header's **⋯** menu (GM only; 0.34.0; under the name in 0.33.0, in the header before that; shown when the character has copies; on a copy itself it reads **Restore this backup…**) picks a copy, newest first, then asks in a red confirmation that says what will happen. Restore:
1. saves the character as it is now as another copy, `<name> - level X` by the same rule (`levelBackup.reason = 'restore'`); if that fails nothing changes;
2. replaces the character's `system` (class levels come with the class items; HP, abilities, everything dnd5e keeps), items, effects and flags with the copy's, with `archivedFlags` put back on each document;
3. keeps the character's id, name, portrait, ownership, prototype token, folder, `core` flags (sheet choice), its Journey (the Journey does not revert) and any queued level backups;
4. with Ashen Gate | Cinders 0.7.0+, calls `api.cinder.rehook(actor)` so the character is re-linked to the Cinders the Cinder records say it bears (the records are the truth; the copy's old links are not used). Older Cinders: the restore happens and warns to run Cinders → Manage → Check. The safety copy is inert and has a new id, so it never holds a bearer link;
5. is all or nothing: if a step fails (the Cinders re-link included), the character is put back as it was just before and re-linked again (the safety copy stays).

Items and effects on both sides are replaced in place by id; the rest are created with their ids or deleted. The live character records `flags['ashen-gate-character-hub'].levelRestore = {opId, backupId, backupName, levelBefore, levelAfter, safetyId, date, by}`; the same opId again does nothing. The copy is not changed. Players are refused in the data layer (`api.levelBackups.restore`), not only by the hidden button. There is no cleanup tool: delete old copies by hand.

API: `api.levelBackups.list(actor)` (copies' ids, names and markers, newest first) and `api.levelBackups.restore(backupActor, {opId})`.
